# attic / bathroom-private｜角色与门节点业务合同、蒙版与网页 GPT edit prompt

本文件是上一份《场景蒙版与角色姿态预案》的业务层补充。它把可见场景、角色动作、门节点和隐私边界写成可供后续产品/运行时消费的语义合同，但当前仍是设计笔记，不是已经接入仓库的 TypeScript contract，也不写入坐标。

网页 GPT edit prompt 的使用前提是：对应房间背景图已经生成并经过人工检查。编辑时只修改指定节点，保持 `1536×1024`、固定三分之四机位、旧木地板透视和纸板舞台风格。浴室 edit 输出还有额外硬门禁：只能有关闭的门外节点，不得出现人物，不得出现浴室内部。

## 1. 共享业务合同

### 1.1 节点记录的最小字段

每个节点后续若进入领域模型，至少应能表达以下语义；在背景图未定稿前，`anchor_ref` 只能引用占位符：

| 字段 | 含义 | 当前约束 |
| --- | --- | --- |
| `scene_id` | 房间稳定标识 | 只使用 `attic` 或 `bathroom-private` |
| `node_id` | 房间内稳定节点标识 | 见本文件第 2、3 节，不随 PNG 版本改名 |
| `node_kind` | 节点的业务角色 | `entry-boundary`、`archive-hotspot`、`visual-anchor`、`privacy-door-outside`、`external-clue-slot` |
| `anchor_ref` | 画面语义锚点 | 只写 `[ATTIC_…]` / `[BATHROOM_…]` 占位符，待背景审核后填坐标 |
| `asset_policy` | 背景/角色/蒙版如何组合 | 背景永远空；角色和前景遮挡分层；浴室门内层永久禁用 |
| `allowed_intents` | 节点允许接收的动作意图 | 只列明可见、可恢复的外部动作 |
| `forbidden_intents` | 必须拒绝的动作意图 | 不以图片生成或失败回退绕过 |
| `state_projection` | 状态如何映射到视觉层 | 业务状态与背景 PNG 分离，避免用图像伪造状态 |
| `failure_policy` | 生成或合成不合格时怎么处理 | 标为失败，退回编辑/重生成，不裁切掩饰 |

### 1.2 统一角色消费规则

- 背景图只提供空舞台；人物从透明角色素材进入，不能被网页 GPT 直接画入房间背板。
- 角色优先复用现有 `walking`、`standing`、`seated`。`climbing-ladder`、`archive-search`、`knock` 只作为待验姿态候选，不能在本轮直接登记成运行时能力。
- 所有新姿态必须延续同一个纸板人偶：圆弧底座、无可见脚、有限棕蓝暖色、耳后褪色红色书签、无文字/水印、透明背景。
- `landing` 表示圆弧底座最低接触点，不是图片中心；`hitbox` 是业务交互范围，待实际背景图确定后单独填写。
- 角色影子、门节点状态、灯光反馈和外部线索不得写死到角色源图；遮挡属于场景蒙版，事件属于业务状态。

### 1.3 统一失败门

以下任一情况直接拒收这次背景或 edit 结果，不进入蒙版适配：

- 镜头改变、画幅改变、地板透视改变、移动区被家具/杂物切断；
- 背景中出现人物、纸板人偶、宠物、身体剪影、文字、UI、logo 或水印；
- 蒙版被用来掩盖缺失的空间锚点，或把角色裁成残缺人体；
- 阁楼缺失真实可通行梯口，或梯口暴露楼下空间；
- 浴室出现开门、门缝透光、室内轮廓、任何卫浴设施或人物；
- 生成结果通过“黑屏/模糊/裁切”假装没有内部，实际仍暗示门内视角。

## 2. attic｜角色与节点业务合同

### 2.1 节点定义

| `node_id` | `node_kind` | `anchor_ref` | 业务意义 | 背景资产策略 |
| --- | --- | --- | --- | --- |
| `attic.ladder.entry` | `entry-boundary` | `[ATTIC_LADDER_ENTRY]` | 阁楼内部可到达的梯口入口 | 梯口、完整侧梁/踏棍和不可透视的下方深处固定在背板；角色不烘焙 |
| `attic.archive.stack` | `archive-hotspot` | `[ATTIC_ARCHIVE_STACK]` | 书堆、旧箱与查档动作的外部热点 | 书堆可作背景主体；近侧遮挡另行分层；书脊/纸页无可读字 |
| `attic.skylight` | `visual-anchor` | `[ATTIC_SKYLIGHT]` | 冷蓝夜景和空间方向锚点 | 只提供背景光和少量不可识别夜色；不是进入点，不承载爬窗动作 |
| `attic.walkable.clear` | `walkable-zone` | `[ATTIC_WALKABLE_CLEAR]` | 人偶从前景接近梯口/书堆的连续地板 | 保护区不输出为可见蒙版，不放置新增家具 |

### 2.2 梯口事件合同

| 意图/事件 | 允许结果 | 必须保持 | 明确拒绝 |
| --- | --- | --- | --- |
| `approach_ladder` | 角色沿移动区到达梯口外侧 | 同一镜头、同一梯口、同一落脚逻辑 | 穿越活板门、瞬移、展示楼下 |
| `contact_ladder` | 角色在梯口外侧扶梁停留 | 圆底在阁楼地板，侧梁可局部遮挡 | 真实脚踩梯级、探身进入黑暗 |
| `climb_ladder` | 仅在后续有批准姿态时播放爬梯候选动作 | 楼下永远不可见；梯口仍是深度边界 | 镜头跟随进入、生成下层房间、手脚从洞内出现 |
| `return_from_ladder` | 角色回到阁楼侧并恢复站立/行走 | 不新增背景、不重排梯口 | 从楼下带出新物件或新角色 |

`climb_ladder` 是动作意图，不等于“打开楼下场景”的授权；没有批准的透明姿态素材时，业务应停在 `contact_ladder`，而不是用现有姿态硬拼。

### 2.3 查档节点合同

| 意图/事件 | 允许结果 | 必须保持 | 明确拒绝 |
| --- | --- | --- | --- |
| `approach_archive` | 角色走到书堆/旧箱外侧 | 移动区连续，书堆不扩张 | 穿过书堆、书堆覆盖全身 |
| `search_archive` | 候选 `archive-search`：上身轻微前倾、手取无字书册/翻无字页 | 书签、头部轮廓、主要手势可读 | 可读标题、真实手写字、写实跪姿和脚部 |
| `finish_archive` | 回到 `standing`，必要时再 `walking` | 背景和天窗位置不变 | 瞬移到梯口或天窗 |

### 2.4 attic 蒙版合同

| 蒙版 ID | 所属层 | 消费者 | 必须保护 |
| --- | --- | --- | --- |
| `attic-ladder-recess-mask` | 背景深度 | `attic.ladder.entry` | 楼下不可见、不可透视、不可进入 |
| `attic-ladder-front-occluder` | 前景遮挡 | `contact_ladder` / `climb_ladder` | 侧梁与角色有真实前后关系；不遮住书签和主要动作 |
| `attic-archive-stack-front-occluder` | 前景遮挡 | `search_archive` | 只遮住由书堆真实边缘产生的下半身/底座局部，不切残角色 |
| `attic-skylight-light-matte` | 背景光 | `attic.skylight` | 冷蓝光不能把角色变成剪影，窗外不升级为新地点 |
| `attic-walkable-clear-mask` | 保护区 | 所有移动事件 | 不可见、不放家具、不改变路径 |

## 3. bathroom-private｜角色与门节点业务合同

### 3.1 绝对规则

`bathroom-private` 的场景资产和网页 GPT edit 结果只允许表现浴室关闭的门外节点。当前本轮的浴室图像中：

- 不出现人物、纸板人偶、宠物、人体剪影或任何身体局部；
- 不出现浴室内部、浴缸、马桶、洗手池、淋浴、镜子、玻璃、浴帘、瓷砖内部、个人物品或室内光；
- 不出现开门、半开门、透明门、门缝透光、门后轮廓、蒸汽、湿脚印或偷窥视角；
- 不用一张“内部图”作为未来可解锁的 fallback；门内层是永久禁用，不是缺失资产；
- 敲门、等待、离场和离场后线索只作为业务事件或外部叠加的设计语义，不得让网页 GPT 把人物或动作画进浴室背景。

如果未来使用透明角色层表达“敲门”，那是独立角色素材与运行时合成，不是本轮浴室背景 edit；背景本身仍必须无人物。

### 3.2 节点定义

| `node_id` | `node_kind` | `anchor_ref` | 业务意义 | 视觉资产策略 |
| --- | --- | --- | --- | --- |
| `bathroom-private.door.outside` | `privacy-door-outside` | `[BATHROOM_DOOR_OUTSIDE_NODE]` | 关闭的浴室门外侧、门框和把手 | 唯一可见的浴室节点；门必须实心、关闭、无透视 |
| `bathroom-private.threshold.outside` | `privacy-boundary` | `[BATHROOM_THRESHOLD_OUTSIDE]` | 门前外侧的停留/停止边界 | 只定义外侧地板，不生成门内区域 |
| `bathroom-private.knock.outside` | `external-action-slot` | `[BATHROOM_KNOCK_POINT]` | 后续可承接敲门意图的门外位置 | 本轮 edit 不画人物；只保证门外门面没有被杂物遮挡 |
| `bathroom-private.external-clue` | `external-clue-slot` | `[BATHROOM_EXTERNAL_CLUE_SLOT]` | 离场后可见的公共、非敏感外部线索槽位 | 独立可撤销叠加；不得从门内投影隐私信息 |
| `bathroom-private.no-interior` | `permanent-deny` | `[BATHROOM_PRIVACY_BOUNDARY]` | 永远拒绝门内内容的系统边界 | 不存在可加载的内部 layer、edit target 或 fallback |

### 3.3 门节点事件合同

| 意图/事件 | 允许结果 | 必须保持 | 明确拒绝 |
| --- | --- | --- | --- |
| `observe_door_outside` | 只观察关闭门外节点 | 门、门框、把手和外部地板不变 | 切到门内、透视门缝、寻找室内细节 |
| `knock_outside` | 记录一次门外敲门意图；后续可由独立透明姿态表达 | 背景仍是关闭门外节点；本轮背景无人物 | 把人物画进背景、打开门、显示回应者/室内 |
| `wait_outside` | 在门外等待或保持不可达状态 | 不用室内光/影子/蒸汽表达占用 | 门后轮廓、声音可视化、锁具特写 |
| `leave_after_knock` | 角色从门外公共动线离开；背景回到 canonical | 门不打开，背景不切镜 | 回头窥视、手碰门缝、留下身体/衣物/脚印 |
| `show_external_clue` | 只在门外槽位显示非敏感、可撤销线索 | 线索不需要解释门内发生了什么 | 室内残留、卫浴用品、个人身份线索 |
| `open_door` / `enter_bathroom` / `peek_inside` | 无业务投影、直接拒绝 | `bathroom-private.no-interior` 永久有效 | 任何内部画面、过渡帧或隐藏 fallback |

### 3.4 bathroom-private 蒙版合同

| 蒙版 ID | 所属层 | 消费者 | 必须保护 |
| --- | --- | --- | --- |
| `bathroom-door-opaque-mask` | 永久隐私边界 | 所有状态 | 门叶/门缝/门框连续不透明；不可透光、不可透视 |
| `bathroom-threshold-stop-mask` | 交互保护区 | 接近、敲门、等待、离场 | 只定义门外停止边界，不输出黑条，不切角色残片 |
| `bathroom-knock-clear-mask` | 动作保护区 | 后续透明 `knock` 姿态 | 保留门外门面空间；本轮背景不得出现人物 |
| `bathroom-external-clue-overlay` | 外部叠加 | `show_external_clue` | 只放公共、非敏感、无文字线索；随事件可撤销 |
| `bathroom-no-interior-layer` | 永久禁用 | 所有生成/编辑/转场 | 不存在内部图、内部蒙版、内部预览或模糊 fallback |

## 4. 可直接复制到网页 GPT 的 edit prompts

### 4.1 通用 edit 前置合同

把下列段落放在每个房间 edit prompt 的开头，再接对应的房间专属段落：

```text
请基于我附上的现有场景图做一次局部编辑，只输出一张编辑后的完整场景图，不要输出拼图、对比图、分镜或文字说明。

必须保持原图的 1536×1024 横向画布、固定三分之四视角、相机高度、地板透视、墙面结构、暖黄灯/冷蓝夜景、旧木地板、斑驳墙面、低饱和棕蓝色调和手绘 2.5D 纸板舞台质感。除我指定的 edit target 外，不改变镜头、裁切、家具布局、移动区、光照方向或房间身份。

这是可叠加纸板人偶的空场景背板：不要在背景中生成人物、纸板人偶、宠物、人体影子、文字、字母、数字、logo、水印、UI、按钮、边框或解释标记。保持前景/中景/背景层次清楚，但不要把角色或状态画死在背板里。

若指定 edit target 无法在原图中被准确修复，请保持未修改区域不动并重新局部处理；不要用新增人物、另一个房间、镜头切换或大幅重绘来掩盖问题。只输出这一张场景图。
```

### 4.2 attic｜梯口 edit prompt

```text
编辑目标：只修复 attic 的 `[ATTIC_LADDER_ENTRY]`、`[ATTIC_LADDER_RECESS]` 与 `[ATTIC_LADDER_STOP]` 节点。

请让左侧偏后的阁楼梯口成为一个清楚、可通行、固定在楼板上的空间入口：矩形活板门/楼板开口，完整的两根木质侧梁和清楚的踏棍，梯子向下连接到不可透视的深色区域。梯口要像真实入口，不要像靠墙装饰梯、断梯、悬空梯或随机道具。梯口下方只保留克制的深度遮挡，绝不显示楼下房间、街道、人物、手脚或任何第二场景。

保留并保护前景至中部的连续旧木地板移动区；梯口位于通道侧边，不得堵住人偶未来从前景靠近梯口的路径。不要新增人物、纸板人偶、脚、角色影子、文字或 UI。不要改变天窗、书堆、书桌、镜头、画幅和整体构图。只修复梯口与其深度关系，输出一张完整的 attic 背景图。

严格禁止：楼下内部、洞口无底深渊、梯上人物、从暗处伸出的手脚、开到能看见下层的活板门、重复梯子、正面立面、俯视平面图、鱼眼、照片级写实、过饱和奇幻色。
```

### 4.3 attic｜书堆与天窗 edit prompt

```text
编辑目标：只修复 attic 的 `[ATTIC_ARCHIVE_STACK]` 与 `[ATTIC_SKYLIGHT]` 节点，不改变梯口和移动区。

请在靠墙/靠斜屋顶的位置整理出少量稳定的旧书堆、旧箱子和查档面，给未来的 `archive-search` 透明角色姿态留下清楚的外侧接近空间。书脊、纸页、箱面全部保持无字、无标题、无符号；书堆不能扩张到前景移动通道，也不能遮住未来角色的头部、耳后褪色红书签和主要查档手势。

请保留后方偏右的小天窗作为冷蓝夜景光源，只增加克制、柔和的蓝色光洗，不要把窗外变成城市、山林或另一个可进入地点，不要把角色画成黑色剪影。不得生成人物、纸板人偶、宠物、角色影子、文字、UI 或水印。梯口、镜头、画幅、旧木地板和暖黄灯光保持原样，只输出一张完整的 attic 背景图。

严格禁止：可读书名/手写档案、杂物堆满地板、天窗占据大半画面、窗外新场景、人物查档、人物爬梯、真实脚部、镜头重构、拼图和多视图。
```

### 4.4 bathroom-private｜关闭门外节点 edit prompt

```text
编辑目标：只修复 bathroom-private 的 `[BATHROOM_DOOR_OUTSIDE_NODE]`、`[BATHROOM_HANDLE]`、`[BATHROOM_THRESHOLD_OUTSIDE]` 与 `[BATHROOM_PRIVACY_BOUNDARY]`。

这是隐私边界场景，不是浴室内部图。请把画面修成一扇完全关闭、实心、不透明的浴室门，以及门外可见的旧木门框、外侧把手、斑驳墙面和门前旧木地板。只表现住宅公共动线一侧；门内永远不可见。门缝只能是中性的实体阴影，不能透光，不能透出任何轮廓、反射、蒸汽或室内物件。

浴室 edit 的硬规则：整张背景图中绝对不能出现人物、纸板人偶、宠物、手、脚、身体剪影、角色影子、浴缸、马桶、洗手池、淋浴、花洒、镜子、玻璃、浴帘、瓷砖内部、毛巾、衣物、洗漱用品、药品、个人物品、门牌、文字、UI 或公共厕所标识。不要添加敲门人物；敲门只是后续独立透明角色层的业务意图，不属于这张背景图。

保留门外的连续移动区与门前停止边界；不要放脚垫、篮子、拖把或其他杂物遮住门外节点。不要打开门、不要生成半开门、不要从门缝看进去、不要用黑屏或模糊伪装内部。状态、敲门、等待、离场和离场后线索都由外部业务/叠加层表达，背景仍保持关闭门外 canonical 场景。只输出一张完整的 bathroom-private 外部背景图。
```

### 4.5 bathroom-private｜离场后外部线索 edit prompt（仅在确有外部线索时）
